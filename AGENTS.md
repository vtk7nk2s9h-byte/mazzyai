# Working style

**Reach for the smallest mechanism that satisfies the request.** Before writing
a new component, page, or piece of state, check whether a platform primitive
already does it:

| Need | Use | Not |
| --- | --- | --- |
| Show more detail on demand | `<dialog>` + `showModal()` | a custom overlay, a new route |
| Disclosure / accordion | `<details>` / `<summary>` | a state machine per row |
| Blurred modal scrim | `::backdrop` (`backdrop:backdrop-blur-sm`) | a fixed overlay div |
| A one-off variation | props on the existing component | a parallel component |

Rules of thumb:

- If a request can be met by editing a few lines in an existing file, do that
  instead of adding files.
- Don't restructure a working component to bolt on a small feature. Splitting a
  server component into client sub-components to add one interaction is almost
  always the wrong trade.
- Ask before building anything that spans multiple new files for a request
  phrased as a small addition.

# Project facts worth knowing

- **Prisma 8, not 7.** Contract-first: `src/prisma/contract.prisma` (no
  `schema.prisma`, no `@prisma/client`, no `generator`/`datasource` blocks).
  Run `pnpm prisma contract emit` after every contract edit. The
  version-matched reference is `.claude/skills/prisma-8/`.
- Query shapes that are easy to get wrong: `orderBy` takes a callback returning
  a direction — `.orderBy((f) => f.startedAt.desc())`. Relations load with
  `.include('agent', (a) => a.select('name'))`.
- `cuid()` is rejected by the SQL PSL provider (despite appearing in its own
  error text); ids use `uuid()`. `Json[]` columns cannot have a default, so
  creates must pass the array explicitly (e.g. `rawEvents: []`).
- **Postgres runs in Docker on port 5433**, not 5432 — this machine has a
  native PostgreSQL service that already owns 5432 and answers `localhost`
  first. `docker compose up -d`, then `pnpm db:seed`.
- `app/lib/call-data.ts` imports the Prisma client, so it must never be
  imported from a `'use client'` file. Presentational helpers live in
  `app/lib/utils.ts` for that reason.
- `app/lib/data.ts`, `app/lib/actions.ts`, `app/query/route.ts` and
  `app/seed/route.ts` are Next.js Learn leftovers still on postgres.js against
  Neon (`POSTGRES_URL`). They query tables the contract does not define.
- `package.json` is `"type": "module"`; PostCSS config is `.mjs` and Tailwind
  config uses imports, not `require()`.
